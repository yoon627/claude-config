# lesson-fix-scoped-to-one-repo — 한 repo 에 하드코딩해 고치면, 실패 모드는 안 덮인 repo 로 옮겨간다

2026-08-12 에 "레포가 조용히 밀리는" 실패를 고쳤다. 2026-08-31 에 **같은 실패가 다른 repo 에서** 그대로
재현됐다. 고쳐진 것은 실패 모드가 아니라 그 repo 에서의 증상이었다.

## 무슨 일이 있었나

- **2026-08-12 조치**: (1) autopull 훅의 dirty 게이트 제거, (2) 세션 브리프에 "뒤처짐 + 왜 못 따라잡았나"
  신호 추가. 둘 다 대상이 `~/.claude` 로 고정됐다 — 훅은 `git -C ~/.claude`, 브리프는
  `repoDir = CLAUDE_BRIEF_REPO || ~/.claude` 와 라벨 문자열 `~/.claude`.
- **2026-08-31 재현**: 작업 repo(knowledge_base)가 origin 보다 37커밋 뒤처지고 plan 편집이 3일간
  미커밋으로 방치됐는데 **아무 신호도 없었다.** 그 repo 는 자동 pull 도, 밀림 경고도, 미커밋 경고도
  대상이 아니었다.
- 확인 방법이 남긴 증거: `CLAUDE_BRIEF_REPO` 로 브리프를 그 repo 에 겨누자
  `~/.claude 1010커밋 뒤처짐 — 브랜치가 adapter-sandbox 라 자동 pull 이 돌지 않는다(훅은 main 에서만)`.
  **계산은 맞고 라벨과 원인이 둘 다 거짓**이었다. 하드코딩은 확장을 막을 뿐 아니라, 확장하는 순간
  거짓말을 하게 만든다.

## 왜 이렇게 됐나 (3 Whys)

1. 왜 다시 발생했나 → 신호가 그 repo 를 보지 않았다.
2. 왜 안 봤나 → 감시 대상이 상수로 박혀 있었다(`repoDir` 기본값, 라벨 문자열).
3. 왜 상수로 박았나 → 그때 아픈 곳이 `~/.claude` 하나였고, **아픈 곳을 고치는 것과 그 병을 고치는 것을
   구분하지 않았다.** 일반화는 비용이 들고 그 자리에서는 이득이 안 보인다.

## 그래서 무엇을 하나

- **수정이 "대상"을 상수로 갖는다면, 그 상수가 유일한 대상인지 물어본다.** 아니라면 최소한 *왜 지금은
  하나로 충분한지* 를 남긴다. 남기지 않으면 다음 사람은 그것이 결정인지 사고인지 알 수 없다.
- **라벨·원인 문구를 대상에서 유도한다.** 상수 라벨은 확장 시 조용히 거짓이 된다 — 없는 신호보다
  나쁘다(사용자가 엉뚱한 곳을 고치게 만든다).
- **처방이 다르면 신호를 나눈다.** `~/.claude` 는 자동 pull 훅이 있으니 "왜 훅이 못 따라잡았나"가 답이고,
  다른 repo 는 훅이 아예 없으니 "직접 pull 해야 한다"가 답이다. 같은 문장을 재사용하면 두 번째 대상에게
  **고칠 수 없는 처방**을 준다.
- **신호를 넓힐 때는 잡음 예산을 먼저 실측한다.** 이번 확장에서 기준 ref 를 `origin/HEAD` 로 폴백시키려다
  리뷰 실측으로 막혔다 — worktree 68개 중 60개(=push 하지 않는 것이 규약인 브랜치들)가 "수백 커밋
  뒤처짐"으로 걸렸다. 잡음이 된 신호는 꺼진 신호와 같다.

## 남은 한계 (정직하게)

넓힌 신호도 **캐시된 remote-tracking ref** 로 판정한다. 그 ref 를 갱신할 주체가 없으면 밀림은 여전히
안 보인다 — 이번 사건이 정확히 그랬다(`refs/remotes/origin/dev` 가 2.7일 얼어 있는 동안 원격은 37커밋
앞서 있었다). 그래서 후속으로 (a) async fetch 훅과 (b) "N일째 fetch 하지 않았다 — 밀렸는지 알 수 없다"
를 넣었다. **모르는 것을 침묵으로 두지 않고 모른다고 말하게 하는 것**이 두 번째 축이다.
