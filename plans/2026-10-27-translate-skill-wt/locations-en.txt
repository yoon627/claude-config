F.1 | Quick Git worktree management — list/switch/create+dlc/remove. `/wt <N>` or an existing worktree name switches to that worktree; any other text (a request) picks a slug without confirmation, creates a new worktree and works inside it with `dlc`. The `?` prefix (`/wt ? <vague description>`) is question mode — it refines the requirement with AskUserQuestion, then joins the same creation path.
F.2 | Use when the user calls `/wt`, `/wt <N>`, `/wt <existing name>`, `/wt <request>`, `/wt ? <vague description>` or `/wt rm <name>`, or when dlc starts a file-changing task outside a worktree and creates a worktree.
I.1 | Interpret `args` by these rules: ‖ | (empty) | list |
I.2 | | `<integer N>` | switch to the Nth worktree |
I.3 | | `rm <name>` | remove |
I.4 | | **exact match** with an existing worktree branch | switch to that worktree |
I.5 | | `?` prefix (`? <vague description>`) | question mode — refine the requirement with AskUserQuestion, then join the "request" path |
I.6 | | any other text (a request) | derive a slug → create the worktree (no confirmation) → work inside it with `dlc` |
I.7 | **Interpretation order** (evaluate from the top, **settle at the first match** and do not look at later rules — this order, not the table row order, is the single source of precedence)
I.8 | 1) empty → list. 2) first token `rm` → remove (do not use `rm` as a worktree name).
I.9 | 2.5) first non-space character is `?` → **question mode** (Question mode section — the rest after removing `?` is the seed to refine, then join request). If the first character is `?`, as in `?rm foo` or `?123`, it is question mode regardless of tokens, integers or exact matches.
I.10 | 3) the whole argument is an integer → switch (if out of range, notice + list). 4) the whole argument exactly matches an existing worktree branch → switch. 5) everything else → treated as **a request** (request section).
